# M3 — IPCA+ scenarios and Selic quote support

Implemented on 2026-09-29 with verified calendar coverage extended through 2050. This milestone adds no dependency, migration, runtime, or localization infrastructure.

## Supported behavior

Official CSV normalization now recognizes exact names for no-coupon Tesouro Prefixado, no-coupon Tesouro IPCA+, and Tesouro Selic. IDs remain `<kind>:<ISO maturity>` (`prefixado`, `ipca`, `selic`). Coupon-bearing instruments, RendA+, Educa+, and other names remain explicitly excluded and reported. Existing databases acquire the additional quotes on the next explicit sync; there is no automatic import.

IPCA+ uses the same isolated anchored scenario engine as Prefixado, with annual **real** yields. Purchase selects BuyPU/BuyYield/D+1; mark-to-market selects BasePU/SellYield/D0; morning early redemption selects SellPU/SellYield and the approved historical D+1/D0 convention. Each scenario holds its quote date, settlement date, remaining term, and implied indexation base fixed. It does not estimate future IPCA, reconstruct an official VNA, or calculate a nominal future maturity amount. Prefixado's standalone BRL 1,000 redemption validator is never applied to IPCA+.

The offline demo includes a raw official IPCA+ 2015 quote dated 2012-02-17, with separate fixture version `ipca-2012-v1` and official CSV provenance. Both demo instruments use the original verified 2012–2015 calendar. Prefixado remains the default and retains its original fixture, price, and calculation. Explicit demo links select each instrument's own date and yield; the Prefixado-specific slider is not shown for IPCA+. Normal forms, shocks, JSON, and CLI reproduction use the shared service.

Selic appears in synchronized market/history views with official PU Base and explicit quote dates. Its displayed source yield is labeled as a **spread**, not the current Selic rate. No Selic yield shock, duration/convexity, hold-versus-early-exit, or theoretical repricing is enabled; all scenario contexts return `unsupported`. Quantity-based portfolio valuation belongs to M4 and will consume the stored official BasePU.

## Independent evidence

See [M3 fixtures](../internal/pricing/testdata/M3_README.md). Three official IPCA+ rows provide nine context baselines, each with zero and ±100 basis point hypothetical shocks. Python standard-library Decimal at 60 digits independently discounts one fixed indexation anchor per context. Expected values are committed and not regenerated by Go tests. The reference count uses full weeks/remainders minus verified holidays and a separate daily enumeration.

Application tests cover magnitude, direction, zero shock, exact dates, missing pairs, numeric/maturity/calendar bounds, demo/synced provenance, and one-day sensitivity. CLI/API/HTML tests verify shared numeric output and English real-yield explanations. Parser, sync, and storage tests cover the expanded supported set, unsupported exact-name exclusions, idempotency, and failure preservation. Selic tests verify stored BasePU and rejection of every scenario context.

## Calendar and scope limitations

Synchronized scenarios use the new `anbima-2002-2050-v1`, preserving every date from the prior 2002–2032 fixture and adding 18 official annual ANBIMA tables with per-source hashes and retrieval dates. Both previous fixtures remain unchanged. Demo scenarios retain `anbima-2012-2015-v1`. Dates outside the selected coverage return `calendar_out_of_range`; no holidays are guessed. The 2050 endpoint covers the latest no-coupon IPCA+ maturity in the inspected source snapshot.

Independent expectations for IPCA+ 2050-08-15 use DU 5994 for purchase and 5995 for BasePU/early redemption on quote date 2026-09-04. Calendar tests verify overlap with the entire previous range, annual counts, 2050 Carnival, coverage bounds, and the four-digit Christmas date in ANBIMA's 2040 HTML table.

Standalone IPCA+ settlement-price reconstruction is not implemented. The official PU supplies the same-date indexation anchor required by V1; numerical scenario validation is not a claim to reproduce every detail of official VNA projections or executable settlement prices. Early-redemption scenarios retain the morning/normal-market limitations approved in M2. All amount-based results are gross.

Portfolio editing/valuation is still M4. M5 accessibility and release checks remain planned. Broader usability improvements and Brazilian Portuguese support are explicitly deferred until the existing V1 plan is complete, as requested by the maintainer.
